# Review integration contract

The supported boundary is a customer-controlled document intake or human review workflow alongside an existing ATS. No Workday/Greenhouse connector, hiring decision integration or customer gateway acceptance is claimed. The private deployment requires the customer's verified TLS/SSO gateway and approved pinned artifacts; see [private pilot](PRIVATE_PILOT.md) and [release gate](COMPANY_RELEASE_GATE.md).

## Versioned review endpoint

`POST /api/v1/review` accepts exactly one of these JSON objects:

```json
{"text": "Synthetic resume content"}
```

```json
{"filename": "synthetic.pdf", "b64": "BASE64_PDF_BYTES"}
```

The PDF example shows the request shape, not executable fixture data. Extra keys, directives, callback URLs and model options are rejected with 422. Existing body/content-type/UTF-8/size limits apply: 7 MiB JSON body, 5 MiB raw PDF, 100,000 text characters, at most 20 PDF pages and a 90-second inference deadline. This endpoint shares the worker, request budget and recovery state with `/analyze`; it is not a second queue or unbounded service. The gateway example applies its analysis limits to both paths.

Send `Content-Type: application/json` and a single correct Content-Length. In private mode, trusted gateway authentication is required before body parsing. Keep the backend unreachable from public clients. API tokens stay on the gateway, never in browser code. Do not log the request body at any layer.

## Response 1.0

The response has a fixed key set with enumerated strings, booleans and bounded observation counts. It includes `schema_version: "1.0"`, `analysis_schema_version: "2.0"`, `policy_version: "2.0"`, `purpose: "human_review_assistance"`, `input_mode` (text/pdf), `analysis_status` (complete/partial/unscorable) and `decision` (no_signals_detected/review_recommended/insufficient_evidence).

`observations` contains exactly five categories: direct_instruction, keyword_repetition, keyword_density, semantic_variance and pdf_structure. Each contains `count` and `review_trigger_count`, nonnegative integers whose totals cannot exceed 4096 findings. These counts are observations, not evidence of intent or calibrated probabilities.

`coverage.modules` contains exactly a/b/c with statuses ok/not_applicable/unsupported/error. `coverage.has_limitations` is a boolean. `coverage.pdf_visibility` is incomplete for PDFs and not_applicable for text; a completed trace analysis must not be interpreted as full visibility assurance. `automatic_rejection_allowed` and `authenticity_verified` are always false.

The projection excludes source text, names, extracted excerpts, findings explanations, arbitrary identifiers/metadata, filenames, image previews, reason strings and experimental scores. Unknown policy/schema/finding contracts return a generic 503, not a partly filtered success. The same validated worker analysis produces the original detailed `/analyze` response for the human evidence UI. The projection does not mutate a PDF, create a sanitized resume, extract verified employment facts or make the original safe to feed into an LLM. Review outputs can still be sensitive when linked to a candidate.

`X-Request-Id` is generated by the HTTP parent for correlation; responses are no-store. These UUIDs are not stable candidate identifiers or immutable audit records. The service emits content-free route/status/duration events. Customer audit storage, authorized appeal/correction workflows, retention and access controls remain customer acceptance requirements.

## Error and compatibility handling

Server-side clients can use `ReviewClient` from `src.integrations.review_client`:

```python
from src.integrations.review_client import ReviewClient, ReviewClientError

client = ReviewClient("http://127.0.0.1:8000", timeout=110)
result = client.review_pdf(pdf_bytes)  # permitted bytes supplied by the caller
```

Catch `ReviewClientError` and retain the case for human handling; never mark an unavailable response clean. Successful results contain `request_id` and the validated `review`. Remote origins require verified HTTPS and an explicit server-side `bearer_token`. The browser SSO gateway example does not implement machine authentication: configure and test the customer's machine identity path separately. Never expose tokens in browser code. The SDK refuses redirects, oversized/ambiguous responses and unsupported schemas; it performs no retries or storage and never echoes server error bodies. Timeout bounds individual socket operations, not total wall-clock duration.

Humans should inspect instruction/repetition evidence in the restricted evidence UI; density/coherence remain advisory. PDF observations need visual/source clarification because full OCR/render visibility is incomplete. Insufficient evidence and errors retain cases for review/retry, never applicant rejection. Customer-owned audit, resolution and appeal storage remain required.

- 400/408: malformed or incomplete/timed-out upload; correct the request.
- 401/403: authentication/host/origin denial; do not bypass the gateway.
- 413/415/422: limits, unsupported type or invalid shape; inspect the source/request.
- 429: shared admission budget/concurrency rejection; use bounded retries with jitter and Retry-After.
- 503/504: missing artifacts, incomplete infrastructure or failed/timed-out work; never treat these as clean documents. Respect Retry-After and retain the case for human handling.

Unknown response versions must fail closed in the client. A request id supports investigation but not automatic replay guarantees. There are no idempotency keys or persisted results; a client timeout may leave processing active until completion/deadline. Do not blindly duplicate a resume submission. Keep existing `/analyze` clients unchanged; new integrations should use the explicit review version.

## Downstream privilege separation

Keep raw resumes, extracted free text and detailed evidence in a restricted human-review path. A downstream decision service should receive only its separately validated, allowed factual fields and this fixed-vocabulary review result. This repository does not provide a verified factual resume parser or hiring scorer. Do not concatenate `/analyze` explanation strings, extracted text or uploaded metadata into instructions for a privileged agent.

Disable tools/network/action permissions on any untrusted extraction step, validate outputs against a closed schema, and make the scoring stage independent of document instructions. Field validation restricts syntax, not truth; human/source verification is still necessary. This review projection limits one output channel but cannot establish end-to-end prompt-injection immunity or protect a compromised native worker from lying about findings.

## Latency and performance evidence

One active analysis, a deadline and route-duration logs are controls, not throughput/SLA measurements. Measure cold start, warm p50/p95/p99, rejection counts, timeouts, worker restarts, memory and cost on the intended host with an approved bundle and representative permitted documents before contracting. Current CI uses synthetic/injected workers or unavailable-artifact behavior and cannot substitute for those measurements.

For prevalence reporting use `python -m src.evaluation.prevalence --help`. Supplied source counts must total at most one billion, cohort size is capped at one billion, and at most 100 assumed prevalence scenarios are accepted. It opens no documents and reports explicit assumptions; its projections do not validate the source dataset or create candidate probabilities.
