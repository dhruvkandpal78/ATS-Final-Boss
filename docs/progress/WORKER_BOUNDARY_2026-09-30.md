# Worker boundary and explicit PDF coverage - 2026-09-30

## Problem and implementation

The inference child handles native PDF parsing. Previously `multiprocessing.Connection.send/recv` exchanged pickle objects across that boundary. A compromised child could exploit executable deserialization in the parent. Also, `poll()` followed by `recv()` bounded only initial readability: a child sending a frame header without its complete body could leave the HTTP request blocked after its inference deadline. This is a source-level hardening finding, not evidence of an exploited PDF vulnerability.

The maintained server now exchanges versioned UTF-8 JSON with `send_bytes/recv_bytes`. Requests are capped at 7 MiB plus 8 KiB of envelope overhead; replies at 8 MiB before body allocation. JSON nesting is bounded at 64 and non-finite numbers are rejected. Response envelopes require a matching per-request identifier, supported integer status and the minimum maintained AnalysisResult shape, including schema version, coverage/module/findings types, score bounds and score availability consistency. Schema validation does not establish the truth of a compromised worker's findings. Generic parent-owned error text replaces child exception messages. Oversized or nonserializable honest-child outputs become a generic 503 response. Invalid child framing/envelopes dispose of the worker and clear readiness.

A dedicated reply thread covers the full frame read and JSON parsing. The request owner enforces the same deadline during send and receive, including final checks before accepting a completed operation; on expiration/shutdown it terminates the child and cleans its parent-owned temporary directory. Termination and cleanup have bounded additional join waits; the inference deadline is not a guarantee of total HTTP wall time. One worker and no waiting analysis queue remain the contract.

PDF API responses additionally expose `coverage.pdf_visibility`, including supported trace completion, pixel visibility support, incomplete optional-content analysis and unimplemented OCR. Existing Module B `coverage_status` refers to completion of its supported trace checks, not complete human visibility verification. Existing scores, decisions, thresholds, detector features and policy version 2.0 are unchanged. An additive metadata change changes the service source hash: a previously frozen candidate manifest must not be edited/re-signed to bypass code-integrity checks; use a new approved versioned candidate bundle for deployment.

A full Windows regression run also exposed an existing disabled-route response reset: rejecting a POST before consuming its small incoming body could discard the 404 response. Disabled routes now reuse the existing bounded 8 KiB/50 ms drain without parsing or invoking inference. A real-socket regression asserts both disabled endpoints respond and never reach the worker.

## Validation

Tests use synthetic text and temporary generated PDFs only. Actual pipes verify JSON transport, oversized-frame rejection and rejection of executable pickle without executing its marker. Other tests exercise stale/wrong replies, private error redaction, NaN/infinity refusal, honest-child success/failure/nonserializable output, shutdown and cleanup. A POSIX-only spawned-child regression writes a frame header and incomplete body, confirms the child reached that point, and verifies timeout and worker disposal. Windows skips this POSIX frame test; Linux hosted CI supplies that evidence. The test suite does not download models or process personal resumes.

Windows Python 3.14.6 offline full suite after the disabled-route repair: **327 passed, 2 skipped, 3 integration tests deselected**. The skips are the existing Windows symlink limitation and the new POSIX partial-frame test. The subsequent stricter success-envelope and deadline changes passed the focused worker/coverage suite: **63 passed, 1 POSIX skip**. Two deterministic post-completion deadline-boundary tests also passed, exercising both sending and receiving without real sleeps. The offline Compose control check passed, and lexical diagnostics still report the same seven authored misses; neither is deployment/accuracy proof. Bandit high-severity scan of app/core/research/inference: no high or medium severity observations; two low severity observations remain. B301 is excluded solely for intentionally provisioned trusted model artifact loading, not IPC. Hosted implementation commit `93088fab716245398f973ea3162ca701c53d1112` passed both push CI [36748992569](https://github.com/dhruvkandpal78/ATS-Final-Boss/actions/runs/36748992569) and PR CI [36748997943](https://github.com/dhruvkandpal78/ATS-Final-Boss/actions/runs/36748997943). Each Linux Python 3.11/3.12 suite reported **339 passed, 3 integration tests deselected**, including the actual POSIX partial-frame regression and both deadline-boundary cases. Installed-wheel smoke, dependency/locked-runtime audits, high-severity scan and isolated container smoke passed. The remaining Starlette test-client deprecation warning is recorded; this is not real approved-model or customer deployment evidence. This verification note is a documentation-only follow-up; runtime source remains byte-identical to that tested implementation.

## Remaining gaps

This removes executable worker message deserialization; it does not establish a complete native-code sandbox. Worker and HTTP parent still share a container cgroup, filesystem/user boundary and inherited environment. RLIMIT_AS is not a separate physical-memory budget. Separate containment design and measured OOM/recovery remain customer release gates. Complete OCR/clipping/occlusion, independent natural manipulation labels, improved multilingual/paraphrase injection detection and calibration remain open. No accuracy, population-zero false-positive, production readiness or absence-of-vulnerabilities claim follows from these changes.

Static hosting was cancelled by the user; no static Pages deployment is active. Actual analysis hosting needs the Python service and approved model artifacts.
